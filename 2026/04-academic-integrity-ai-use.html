Academic Integrity

Your reader or marker should be able to tell:

  • which ideas, words, data, and code came from elsewhere;
  • what you contributed, changed, and understood;
  • what you actually did and what the evidence supports.

Acknowledging help matters, but acknowledgement does not make a prohibited use acceptable.

How To Check An AI-Suggested Reference

  1. Find it: search the exact title in Library OneSearch, Google Scholar, or Crossref.
  2. Open it: follow the DOI or publisher link.
  3. Match it: compare authors, title, year, journal, and publication details.
  4. Read it: check the relevant passage supports your claim before citing.

A working DOI is not enough if it leads to a different paper.

Not found does not automatically mean fabricated. Check for errors; do not cite an unverified reference.

Frequent Referencing Mistakes

Pattern Repair
Missing reference Match citations to references in both directions.
Unsupported factual claim Find evidence for the claim, or qualify/remove it.
Incorrect imported details Check authors, year, title, source type, and publication details.
Association presented as causation Match the claim to the design: an association does not establish causation.
Fabricated AI reference Verify existence and metadata.
Unclear citation scope Place citations so readers can tell which claims each source supports.
Citing an unread source Read the original, or explicitly cite it through the source you actually consulted.

What Can Your Referencing Workflow Catch?

How do you currently insert citations and create your reference list?

  • RMarkdown: citation keys link to a bibliography file; rendering produces citations and references in the configured style.
  • Word with a reference manager: Zotero, Mendeley Cite, or EndNote’s Cite While You Write can link citations to an automatically updated reference list.
  • Manual references: check the text and reference list against each other.

Which issues in our examples would your workflow prevent? Which would still need your attention?

Automation helps keep references consistent. It cannot tell whether you forgot a citation, selected the right source, or represented its findings accurately.

From References To AI Use

AI can still misrepresent its findings, population, or limitations.

  • Cite the evidence: read and cite the original sources you actually checked.
  • Acknowledge the process: explain how you used AI, following NTU and assessment requirements. This does not replace evidence for your claims.
  • Verify independently: check the publisher, Library catalogue, or a bibliographic database.

Use AI to help find or understand sources. Cite the sources you checked, and separately acknowledge how you used AI.

What is the equivalent check when AI produces code or a statistical analysis?

Bodleian: verifying references; APA: documenting AI use. Follow your assessment’s specific instructions.

NTU’s Official Position On AI

NTU’s Academic Integrity Policy expects you to:

  • Keep your own contribution clear; do not present AI-generated work as your own.
  • Use AI to support, not replace, your independent work.
  • Declare AI use in assessments.
  • For proofreading, ask for errors to be identified; make corrections yourself.

Disclosure of AI use is not, by itself, evidence of misconduct. Transparency matters; you must still follow the rules for the assessment.

Your Task: Ask Copilot For R Code

Use the public ggplot2::msleep data from our previous tutorial. One row is a species; vore is diet group and sleep_total is sleep in hours.

We want a small table showing, for each diet group:

  • the number of species with usable data;
  • their average total sleep in hours.

Exclude rows missing either diet group or total sleep. Keep the code simple and readable.

Write your own request in plain English before opening Copilot (in Word or similar). You do not need to know which R functions to ask for.

Build A Clear Request

Compare your first prompt with a partner. Does it explain:

  1. Input: which dataset, what one row means, and which columns matter?
  2. Output: what should one result row contain?
  3. Decisions: what should happen to missing values?
  4. Learning needs: short, beginner-readable R/tidyverse code, with each step explained?

Sentence starters: “My data are…”, “I want a table with…”, “Exclude…”, “Please explain…”

Ask Copilot to clarify anything important rather than silently making assumptions.

Generate, Test, And Revise Once

Use Copilot, then inspect the code before running it in RStudio.

  • Does it use the actual vore and sleep_total columns?
  • Is there one result row per diet group, rather than one overall average?
  • Are missing values handled as requested, and are counts sensible?
  • Can you explain one line and check one group’s average independently?

Revise your prompt once to address a missing detail, unclear explanation, or failed check. If it works already, ask for a way to verify it.

Share one change that made the request clearer, and one check you used. What did you still need to decide yourself?
